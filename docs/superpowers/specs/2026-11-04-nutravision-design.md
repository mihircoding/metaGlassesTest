# NutraVision — Design Spec

Date: 2026-11-04 · Status: awaiting review · Repo: `mihircoding/metaGlassesTest`

## 1. Intent

NutraVision is an iOS nutrition tracker (Cal AI–style AI logging, MyFitnessPal-style layout) for people whose
diet is shaped by a health condition (diabetes, hypertension, kidney disease, …) or a training goal
(bodybuilding, endurance). Meta Ray-Ban glasses let the user look at food, ask for a scan by voice, hear the
name, calories and whether it fits their condition, and say "add it" to log it. Doctors can link to patients
(with patient consent), read their logs, and send recommendations the patient accepts or declines.

**Audience for this build:** demo / portfolio. Free tiers, no HIPAA work, runs on the owner's iPhone + glasses.
Not medical advice; the app says so.

### Decisions made during brainstorming
| Topic | Decision |
|---|---|
| Approach | Evolve the existing SwiftUI app in `ios/`; replace on-device storage with Supabase (online-first) |
| Backend | Supabase free tier: Auth, Postgres + row-level security (RLS), Edge Functions |
| Vision AI | Anthropic Claude (`claude-opus-5-5`, effort `low` for voice latency), called only from an Edge Function; key never on device. Model id is one constant |
| Food data | USDA FoodData Central (FDC) for text + barcode; Open Food Facts (OFF) as barcode fallback |
| "Other health apps" | Via Apple Health (HealthKit) only |
| Health verdict | Deterministic on-device rules, not an LLM |
| Build | Mac + Xcode by the owner; project generated by XcodeGen. Code authored on Windows (no Swift compiler) |

### Success criteria (the demo walkthrough)
1. Sign up as a patient with Type 2 diabetes + Hypertension, goal "lose 0.5 kg/week" → daily targets computed.
2. Glasses Mode: look at a plate, say "scan this" → hear name, calories and verdict (typically ≤ 8 s); say
   "add it" → logged to the right meal, hear the new daily total.
3. Look at a packaged item's barcode → hear the result without a command; "add it".
4. Search "greek yogurt" → USDA generic + branded results; add with a serving size.
5. Diary in MyFitnessPal layout; Progress shows a colored month calendar and a 12-month year heatmap.
6. Log a run manually and import a workout from Apple Health → remaining calories increase.
7. Seeded doctor sends a request → patient accepts → doctor sees the diary → doctor sends lower sodium
   targets → patient accepts → targets and verdicts change.
8. Start the Bodybuilding sample plan, swap a food, keep it as the active plan.

### Non-goals (this build)
Push notifications and realtime updates (pull-to-refresh instead) · offline logging · strength sets/reps ·
direct Fitbit/Garmin/Strava APIs · HIPAA/BAA · doctor license verification · App Store release (Meta's
Wearables SDK is a developer preview) · the Android prototype in `app/` (left untouched).

## 2. Architecture

```
iPhone app (SwiftUI, iOS 17)
 ├─ Meta glasses (MWDATCore + MWDATCamera, already integrated)
 │    camera frames in · TTS out over Bluetooth · glasses mic in (HFP)
 ├─ HealthKit: read workouts, steps, active energy, body mass · write dietary nutrients, body mass
 └─ Supabase
      ├─ Auth: email + password; role (patient | doctor) in sign-up metadata
      ├─ Postgres + RLS (§3)
      └─ Edge Functions (Deno), secrets ANTHROPIC_API_KEY, FDC_API_KEY
           food-search   text | barcode → FDC (→ OFF fallback for barcodes) → FoodItem[]
           analyze-food  JPEG → Claude (items + grams) → FDC per item → AnalyzedItem[]
```

Both functions require a signed-in user's JWT (Supabase default `verify_jwt`).

## 3. Data model (Postgres)

All tables have `id uuid pk default gen_random_uuid()` and `created_at timestamptz default now()` unless noted.
Nutrient columns everywhere: `kcal, protein_g, carbs_g, fat_g, sat_fat_g, sodium_mg, fiber_g, sugar_g`
(numeric, ≥ 0).

**profiles** — `id uuid pk references auth.users on delete cascade`; `role text check in ('patient','doctor')`;
`full_name, email`; `birth_date date, sex text check in ('male','female','unspecified'), height_cm, weight_kg`;
`activity text check in ('sedentary','light','moderate','very','extra')`;
`conditions text[]` (first element = primary; values = ConditionCatalog ids);
`goal_weight_kg, weekly_rate_kg numeric check between -1 and 1`;
`kcal_target, protein_g, carbs_g, fat_g, sat_fat_g, sodium_mg, fiber_g` (active daily targets);
`targets_source text check in ('auto','custom','doctor') default 'auto'`;
`add_exercise_kcal bool default true`; doctor-only: `specialty, license_number`.
Created by an `after insert on auth.users` trigger from `raw_user_meta_data` (role, full_name).
A `before update` trigger rejects role changes.

**food_logs** — `user_id`, `logged_at timestamptz`, `meal text check in ('breakfast','lunch','dinner','snack')`,
`name, brand`, `serving_desc text`, `serving_grams numeric null`, `servings numeric > 0 default 1`,
nutrient columns **per serving**, `source text check in ('manual','search','barcode','glasses_ai','photo_ai','plan')`,
`source_ref text` (FDC id / barcode / OFF code), `ai_confidence text null`, `scan_id uuid null` (groups items
from one photo). Index `(user_id, logged_at)`.

**custom_foods** — `user_id, name, brand, serving_desc, serving_grams`, nutrient columns per serving.

**workouts** — `user_id, started_at, kind text` (running, walking, cycling, swimming, strength, hiit, yoga,
other), `duration_min, kcal, distance_km null, notes, source text check in ('manual','healthkit')`,
`healthkit_uuid text null`, unique `(user_id, healthkit_uuid)`.

**weight_logs** — `user_id, measured_at, weight_kg, source ('manual','healthkit')`, `healthkit_uuid` unique per user.
The newest weight is also copied to `profiles.weight_kg` (by the app), which re-runs TargetCalculator while
`targets_source == 'auto'`.

**diet_plans** — `user_id` (owner), `author_id` (owner or doctor), `condition_id text, name, notes`,
`targets jsonb` (same keys as profile targets), `meals jsonb`
(`[{meal, items:[{name, serving_desc, serving_grams?, …nutrients}]}]`), `is_active bool`.
Partial unique index: one active plan per user.

**care_links** — `doctor_id, patient_id` (profiles), `patient_email text` (as the doctor typed it, so the
Requests tab can label pending links without reading the patient's profile), `status text check in
('pending','accepted','declined','revoked')`, `responded_at`. Unique `(doctor_id, patient_id)`.

**recommendations** — `doctor_id, patient_id, kind text check in ('targets','diet_plan','note')`,
`payload jsonb` (`{targets:{…}}` | `{diet_plan:{name, condition_id, notes, targets, meals}}` | `{}`),
`message text`, `status text check in ('pending','accepted','declined')`, `responded_at`.

### Access rules (RLS on every table)
Helper `is_doctor_of(p uuid) returns bool` (security definer): an `accepted` care_link exists with
`doctor_id = auth.uid()` and `patient_id = p`.

| Table | Owner | Linked doctor | Other |
|---|---|---|---|
| profiles | select/update own | select if `is_doctor_of(id)` | a patient can select a doctor's profile when any care_link (any status) joins them |
| food_logs, custom_foods, workouts, weight_logs | all own | select if `is_doctor_of(user_id)` | none |
| diet_plans | all own | select if `is_doctor_of(user_id)` | none |
| care_links | patient: select + update `status` only | doctor: select own; update to `revoked` only | inserts only via `request_patient` |
| recommendations | patient: select; update `status` to `declined` | doctor: select own; insert only if `is_doctor_of(patient_id)` | accept only via `accept_recommendation` |

### Database functions (security definer, `auth.uid()` checked)
- `request_patient(patient_email text) returns care_links` — caller must be a doctor; looks up the patient by
  email; errors "No patient with that email" if none or if the account is a doctor; upserts a `pending` link
  (re-requesting after declined/revoked resets to pending).
- `respond_care_link(link_id uuid, accept bool)` — caller must be that link's patient; status pending → accepted/declined.
- `accept_recommendation(rec_id uuid)` — caller must be the patient; rec must be pending. `targets` → write the
  profile targets, `targets_source = 'doctor'`. `diet_plan` → deactivate the current plan, insert the plan with
  `author_id = doctor_id`, `is_active = true`. `note` → just mark accepted. One transaction.

### Seed (`seed.sql`)
Demo doctor `doctor@nutravision.demo` and patients (Type 2 diabetes; Hypertension; Bodybuilding), all with
password `demo1234`, accepted links, 30 days of realistic food logs + workouts + weights, one pending
recommendation. Inserted through `auth.users` so the triggers create profiles.

## 4. Edge Functions

Shared TypeScript types:
```ts
type Nutrients = { kcal; protein_g; carbs_g; fat_g; sat_fat_g; sodium_mg; fiber_g; sugar_g } // numbers
type FoodItem = { name; brand?; source: 'usda'|'off'; source_ref; serving_desc; serving_grams?: number;
                  per_serving: Nutrients }
type AnalyzedItem = { name; grams; confidence: 'high'|'medium'|'low';
                      source: 'usda'|'ai_estimate'; source_ref?; nutrients: Nutrients }  // already scaled
```

**`food-search`** — `POST {query?: string, barcode?: string}` → `{items: FoodItem[]}`.
- Text: FDC `/v1/foods/search`, dataTypes Foundation, SR Legacy, Survey (FNDDS), Branded; `pageSize 25`.
  Generic foods → serving "100 g" (the app's gram field covers other amounts); branded → labeled serving
  (`servingSize` + `servingSizeUnit`, `householdServingFullText`).
- Barcode: FDC search by GTIN/UPC (exact `gtinUpc` match, also trying the 12↔13-digit zero-padded form) →
  else OFF `api/v2/product/{code}` → else `{items: []}`.
- FDC nutrient ids: energy 1008 (fallback 2047/2048), protein 1003, carbs 1005, fat 1004, sat fat 1258,
  sodium 1093, fiber 1079, sugars 2000. OFF: `*_100g` fields, sodium g → mg.
- Upstream failure → `502 {error}`; bad input → `400 {error}`.

**`analyze-food`** — `POST {image_base64, media_type}` (JPEG ≤ ~1 MB, ~1024 px long side) →
`{is_food: bool, items: AnalyzedItem[], totals: Nutrients, notes: string}`.
1. Call Claude (`claude-opus-5-5`, `output_config.effort: "low"`, `fallbacks: "default"` for refusals) with the
   image and a structured output (`output_config.format` JSON schema):
   `is_food`, `notes`, `package {brand, product} | null`, and items
   `[{name, fdc_query, grams, cooking_method, confidence, estimate: Nutrients}]`. The prompt tells Claude to
   separate distinct foods, estimate grams using plate (~27 cm), utensils and hands as scale, write `fdc_query`
   in USDA naming style ("Chicken, breast, grilled"), and give its own per-item nutrient estimate.
2. Per item in parallel: FDC search `fdc_query` (Survey FNDDS, Foundation, SR Legacy), take the best hit, scale
   per-100 g nutrients × grams/100 → `source 'usda'`. No hit or FDC error → Claude's `estimate`, `source 'ai_estimate'`.
3. Totals = sum of items. Exact SDK/request shape confirmed against current Claude API docs at implementation.
- Claude failure → `502`; non-food → `200 {is_food:false, items:[]}`.

### ConditionCatalog

fiber g, guidance text (recommend/avoid lists, carried over from the current `MedicalCondition`), optional
keyword flags, and a one-day sample plan (meals → foods with portions and nutrients).

| t1_diabetes | Type 1 diabetes | 20/45/35 | 2300 | 10 | 30 |
| hypertension | Hypertension (DASH) | 18/55/27 | 1500 | 6 | 30 |

Keyword flags (name contains, case-insensitive; each list includes at least these): celiac → bread, pasta,

sushi, sashimi, raw, unpasteurized, deli, salami, pâté, swordfish, king mackerel, shark, tilefish. `// ponytail:` keyword match — misses unnamed ingredients.

### Targets (`TargetCalculator`)
- BMR: Mifflin–St Jeor (male +5, female −161, unspecified −78). TDEE = BMR × activity
  (1.2 / 1.375 / 1.55 / 1.725 / 1.9).
- kcal = TDEE + `weekly_rate_kg` × 7700 / 7, then floor at 1500 (male) / 1200 (female) / 1350 (unspecified).
  Pregnancy: +300 kcal and a negative rate is clamped to 0. Missing body stats → 2000 kcal.
- Macros from the primary condition's split: protein & carbs g = kcal × % / 4, fat g = kcal × % / 9.
- Limits across all selected conditions: sodium = min, sat fat g = kcal × (min %) / 9, fiber = max.
- Recomputed and saved only while `targets_source == 'auto'`. Editing a target sets `custom`; accepting a
  doctor recommendation sets `doctor`. "Reset to recommended" sets `auto`.
- Daily calorie goal shown = kcal target + (today's exercise kcal if `add_exercise_kcal`).

### Verdict (`HealthVerdict.evaluate(item, targets, consumedToday, conditions)`)
Item nutrients are already scaled to the amount being logged. Each rule yields a reason with severity
`bad`, `caution` or `good`.

| Applies to | Rule |
|---|---|
| everyone | item sodium > 40 % of daily limit → caution; consumed + item > daily limit → caution |
| hypertension, heart_disease, ckd, liver | the two sodium rules above become **bad** |
| everyone | item sat fat > 30 % of daily limit → caution |
| heart_disease, high_cholesterol | item sat fat > 50 % of daily limit → **bad** |
| t1/t2_diabetes | net carbs (carbs − fiber) > 45 g → bad, > 30 g → caution; sugar > 25 g → bad, > 15 g → caution |
| ckd | item protein > 30 g → caution |
| everyone | consumed + item kcal > daily goal → caution ("puts you X over today") |
| weight_loss | consumed + item kcal > daily goal × 1.1 → **bad** |
| celiac / pregnancy keyword hit | **bad** ("may contain gluten" / "not advised during pregnancy") |
| ibs keyword hit | caution ("high-FODMAP ingredient") |
| bodybuilding, endurance | protein ≥ 10 g per 100 kcal → good ("great protein source") |
| endurance | carbs ≥ 50 % of item kcal → good |
| everyone | fiber ≥ 5 g → good |

Result: any bad → **Not recommended**; else any caution → **OK in moderation**; else **Good fit**. Reasons
are sorted bad → caution → good; the first two are shown and spoken.

### VoiceCommand parser
Lowercased words → `scan | add(meal?) | skip | status | exit | none`.
scan: "scan", "what is this", "what's this", "what am i eating" · add: "add", "log", "yes", "yeah", with an
optional meal word · skip: "skip", "no", "cancel", "nope" (whole words only) · status: "how am i doing",
"calories left", "remaining" · exit: "stop glasses", "exit".

### MealSlot (time → meal)
04:00–10:59 breakfast · 11:00–14:59 lunch · 17:00–21:29 dinner · otherwise snack.

### ExerciseCalories
kcal = MET × weight kg (default 70) × hours. MET: running 9.8, walking 3.5, cycling 7.5, swimming 6.0,
strength 5.0, hiit 8.0, yoga 2.5, other 4.0.

## 6. Glasses Mode and the voice loop

`GlassesSession` targets Meta Wearables DAT SDK 1.0 (`github.com/meta/meta-wearables-dat-ios`):
`Wearables.shared.createSession(deviceSelector: AutoDeviceSelector(wearables:))` → `session.start()` →
`session.addCamera(config: StreamConfiguration(videoCodec: .raw, resolution: .low, frameRate: 15))` →
`camera.stream.start()`. Frames from `stream.videoFramePublisher` feed Vision barcode detection about every
0.35 s (existing loop). A scan calls `stream.capturePhoto(format: .jpeg)` and takes the full-quality image from
`stream.photoDataPublisher`, falling back to the latest frame after 3 s.
`VoiceLoop` owns the speech recognizer (on-device, glasses mic over Bluetooth HFP), an `AVSpeechSynthesizer`,
and a single `pending` scan.

```
idle ──"scan"──▶ analyzing ──result──▶ speaking ──▶ awaiting confirm ──"add"──▶ logged ─▶ idle
  └─barcode seen──▶ looking up ─┘                     └──"skip" / new scan / 60 s──▶ idle
```

- Recognition pauses while TTS speaks and restarts after `didFinish`, so the app never hears itself. Each
  final transcript restarts the recognizer.
- Spoken result: "<name or 'N items'>, about <kcal> calories and <protein> grams of protein. <Verdict> for
  your <primary condition> plan: <reason 1>. Say add it or skip." Low confidence prefixes "I think this is".
- "add it [to <meal>]" → insert one food_logs row per item with a shared `scan_id`, meal from the command or
  MealSlot → speak "Added. <consumed> of <goal> calories today." AI items are stored as `servings = 1`,
  `serving_desc = "<grams> g"`, `serving_grams = grams`, nutrients = the already-scaled values.
- "how am I doing" → remaining kcal and the limit with the highest % used.
- The on-screen card mirrors the pending scan; the user can adjust grams per item and tap Add or Skip.
- Same loop without glasses: phone camera photo for AI scans, VisionKit `DataScannerViewController` for
  barcodes, phone mic and speaker.
- Errors are spoken and shown: glasses not connected; "I don't see food, try again"; "Couldn't analyze, try
  again" (network / 5xx); unknown barcode → "I couldn't find that product, try scan this".

## 8. Apple Health (`HealthSync`)
- Permission requested from More → Apple Health (not at launch).
- On app foreground and pull-to-refresh: read workouts and body mass since the last sync (anchored queries)
  → upsert workouts / weight_logs by `healthkit_uuid`; read today's steps and active energy for display only
  (only workout kcal is added to the calorie goal, so nothing is counted twice).
- On food log insert: write an `HKCorrelation(.food)` with energy, protein, carbs, fat, sat fat, sodium, fiber,
  sugar, tagged with metadata `HKMetadataKeyExternalUUID = food_logs.id`; on delete remove the sample with that
  tag. Manual weight logs are written as body mass.

## 9. Error handling
- Network/Supabase errors → inline banner with Retry; nothing is silently dropped (an insert that fails keeps
  the sheet open with the entry intact).
- Auth expiry → supabase-swift auto-refresh; refresh failure → back to sign in.
- Edge Functions return `{error}` with 400/401/502; the app maps these to user text.
- Glasses SDK errors keep the existing alert path; Glasses Mode stops cleanly on disconnect.

  row, combining to the final verdict), VoiceCommand (each phrase and the "know"/"no" whole-word case),
  VoiceFlow transitions, SpokenText copy, MealSlot and DayStatus boundaries, ExerciseCalories, PatientFlags.
- Edge Function shared logic: `node --test supabase/functions/tests` on this machine — FDC/OFF nutrient

- `supabase/tests/rls_check.sql`: as the demo doctor, reading an unlinked patient's food_logs returns 0 rows;

- Manual on device: the §1 walkthrough. I can't build or run iOS on Windows; the owner runs Xcode builds and

## 11. Build order (each phase leaves a runnable app)
1. **Foundation:** rename to NutraVision, `project.yml`, Supabase migration + seed + RLS check, auth +
   onboarding, Backend/AppModel replacing UserDefaults, saturated fat, Core (Targets, ConditionCatalog).
2. **Food data and AI:** `food-search` and `analyze-food` with node tests, Add Food / Create Food / Food detail,
   Diary + Dashboard in MyFitnessPal layout, photo scan + phone barcode, Verdict.
3. **Glasses voice loop:** GlassesSession, VoiceLoop, VoiceCommand, MealSlot, scan card.
4. **Doctor ↔ patient:** request/respond/accept functions in the UI, Care Team, doctor tabs, recommendations.
5. **Health and goals:** weight goals + weight log, exercise logging, HealthSync, Progress month/year
   calendars and charts, Conditions & Diet Plans editor.

## 12. Owner setup (in `docs/SETUP.md`)
Create a Supabase project, a USDA FDC API key (api.data.gov) and an Anthropic API key; `supabase link`,
`supabase db push`, run `seed.sql`, `supabase secrets set ANTHROPIC_API_KEY=… FDC_API_KEY=…`,
`supabase functions deploy food-search analyze-food`; put the project URL + anon key in
`ios/NutraVision/App/Config.swift`; `brew install xcodegen && cd ios && xcodegen`; set the signing team and

## 13. Risks
- Meta Wearables SDK is a developer preview: API changes and limited distribution. Mitigation: the phone
  camera path gives the same features without glasses.
- Glasses mic quality over HFP in noisy rooms → short command grammar plus on-screen buttons.
- FDC match quality for AI queries → Claude writes FDC-style queries; mixed dishes searched in FNDDS; the
  AI-estimate fallback is labeled; the user can edit grams before adding.
- Claude cost: one Opus 5.5 image call per scan, roughly 1–2 cents; fine for a demo. Switching to
  `claude-sonnet-5-5` halves it and is a one-line change.
- Code is written without a Swift compiler, so the first Mac build will surface compile errors to fix.
